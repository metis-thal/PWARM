# P0.1 物理引擎选型报告

> 阶段：Phase 0 技术预研 | 日期：2026-08-27
> 项目：pymo — 物理世界 AI 推演模型

## 一、候选方案

| 代号 | 方案 | 说明 |
|------|------|------|
| A | Pymunk | 2D Chipmunk 的 Python 绑定，成熟、易用 |
| B | Bullet3 (pybullet) | 3D 刚体物理引擎，工业级，碰撞检测强大 |
| C | Taichi Lang | 高性能数值计算 DSL，可自写物理内核 |

## 三、核心约束分析

项目有两条不可妥协的约束，直接决定了选型：

1. **真值 / AI 模型分离**：物理引擎是绝对真值，AI 是学习拟合模型。AI 需要以**时序数据形式**完整读取世界状态（位置、速度、受力、温度场、流场）。商业引擎（Pymunk/Bullet）将内部状态封装为黑盒，难以按需导出全部物理场张量，且无法在方程层面强制守恒律修正。

2. **零硬编码现象**：燃烧、断裂、流动必须由底层方程推演涌现。Pymunk/Bullet 只提供刚体碰撞，热力学、流体、相变、化学反应完全不在其能力范围内——这些必须自写。引入商业引擎反而造成「刚体用引擎、其他自写」的双轨割裂，违背四层架构单一内核原则。

## 四、推荐：D — 自研物理内核（Python + Numba + SciPy）

**理由**：
- 满足真值/AI 分离：内核完全可控，可导出任意物理量张量供 AI 学习
- 满足零硬编码：热/流/材料/化学全部在自写规则层实现
- 守恒律可强制：Verlet 辛积分（P0.4 实测能量漂移 ~1e-15）+ 动量/能量投影修正
- 与既定技术栈一致：计划已锁定「Verlet积分、有限元、Python+Numba」
- P0.4 已验证自研 Verlet 在 1000 步内能量漂移达机器精度，数值稳定性无忧

**放弃现成引擎的代价与对策**：
- 碰撞检测需自实现：2D 用 SAT + 空间哈希；3D 用 GJK/EPA + BVH（阶段二）
- 流体求解需自实现：SPH 或简化 NS（阶段二）
- 对策：分阶段增量实现，每阶段可视化验收（符合项目避坑准则 #4）

**不选 Taichi 的理由**：Taichi 性能强但生态绑定重、与 PyVista 可视化集成成本高，且项目已选定 PyVista 作为统一渲染层。Numba 足以满足当前规模，且与 SciPy/NumPy 生态无缝。

## 五、结论

**决策：采用 D 自研物理内核（Python + Numba + SciPy），渲染层统一 PyVista。** 拒绝引入 Pymunk/Bullet 作为核心物理引擎（仅可作阶段一碰撞检测的参考实现）。

## 六、主要风险

1. **碰撞检测自研成本**：2D SAT 简单，3D GJK/EPA+BVH 复杂 → 阶段二专项攻坚，先 2D 验证算法。
2. **流体/材料模拟精度**：SPH/NS 简化易失稳 → 分阶段、小规模验证，多物理场耦合逐步接入。
3. **性能瓶颈**：纯 Python 在粒子/网格规模增大时受限 → Numba JIT + 阶段四 Ray 并行 + PINN 加速。
